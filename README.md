# 2Nouta

проект по ооп

Каталог автомобилей Lada на двух ноутбуках, которые общаются по TCP-сокетам. Клиент (Ноутбук 2) получает от сервера (Ноутбук 1) список моделей (Granta, Vesta, Niva Legend, Niva Travel, Largus, Iskra) и показывает его выпадающим списком. Выбранная модель появляется на обоих экранах: 3–5 фото с переключением, подпись автора и лицензии фото и краткие характеристики. Фото и характеристики хранятся только на сервере, клиент получает их по сети. Окна сделаны на Tkinter, для JPEG используется Pillow.

Характеристики взяты из статей ru.wikipedia.org (CC BY-SA 4.0), фото — с Wikimedia Commons (только public domain, CC0, CC BY и CC BY-SA). Чего нет в статье, в окне показано как «нет данных».

Программа собирается в один файл `2Nouta.exe` для Windows. Один и тот же exe запускается и как сервер, и как клиент.

## Файлы

- `main.py` — точка входа: спрашивает в консоли режим (`1` — Сервер, `2` — Клиент) и запускает нужное окно
- `server.py` — класс `ServerApp`: окно с выбранной моделью и TCP-сервер, который раздаёт каталог из папки `data`; запускается на Ноутбуке 1
- `client.py` — класс `ClientApp`: окно со списком моделей, запускается на Ноутбуке 2
- `model_view.py` — класс `ModelView`: блок с фото, подписью и характеристиками, общий для сервера и клиента
- `discovery.py` — автопоиск сервера в сети: ответчик на `DISCOVER` для сервера и сканер подсети для клиента
- `config.py` — порты, размер буфера и сообщений, названия команд и настройки поиска
- `fetch_data.py` — скачивает данные каталога в `data/models.json` и `data/photos/<id>/`
- `data/` — данные каталога, нужны только серверу
- `build.ps1` — сборка `dist\2Nouta.exe`

## Сборка

Нужен Python 3 с https://www.python.org/downloads/ (с ним ставятся Tkinter и лаунчер `py`). Python из MSYS2/Cygwin не подойдёт.

Если папки `data` ещё нет, сначала скачайте данные (нужен интернет; занимает около минуты, потому что между запросами пауза). Перед этим замените в `USER_AGENT` в `fetch_data.py` заглушку `YOUR_EMAIL@example.com` на свой email, как просят правила Wikimedia:

```
py -3 fetch_data.py
```

Затем в PowerShell в папке проекта:

```
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт создаст `.venv`, поставит в неё PyInstaller и Pillow и соберёт `dist\2Nouta.exe` вместе с папкой `data`. Файл автономный: Python и библиотеки упакованы внутрь, его можно просто скопировать на другой компьютер с Windows 10/11 (64-бит) и запустить.

Exe не подписан, поэтому при первом запуске Windows SmartScreen может показать «Windows защитила ваш компьютер»: нажмите «Подробнее» → «Выполнить в любом случае».

## Запуск

Запустите `2Nouta.exe` (двойным кликом или из консоли). Откроется консоль с вопросом:

```
1 - Сервер
2 - Клиент
Выберите режим:
```

Введите `1` или `2` и нажмите Enter. На другой ввод программа спросит ещё раз. После выбора откроется окно сервера или клиента. Когда окно закрыто или произошла ошибка, консоль пишет, что случилось, и ждёт нажатия любой клавиши.

Режим можно передать аргументом, тогда вопроса не будет: `2Nouta.exe server`, `2Nouta.exe client` или `2Nouta.exe client 192.168.0.193`.

### В двух окнах на одном компьютере

1. Запустите `2Nouta.exe` и выберите `1` (Сервер).
2. Запустите тот же `2Nouta.exe` ещё раз и выберите `2` (Клиент).

Клиент сам найдёт сервер на этом же компьютере. Два экземпляра друг другу не мешают: каждый распаковывается в свою временную папку, а файл `last_ip.txt` рядом с exe пишет только клиент. Сервер на одном компьютере может быть только один.

### На двух компьютерах

1. Подключите оба компьютера к одной сети Wi-Fi.
2. Скопируйте `2Nouta.exe` на оба компьютера.
3. На Ноутбуке 1 запустите exe и выберите `1`.
4. На Ноутбуке 2 запустите exe и выберите `2`.

**Брандмауэр Windows.** Сервер принимает входящие подключения на TCP-портах `55555` (команды) и `55556` (поиск). При первом запуске сервера Windows покажет окно брандмауэра: разрешите доступ и отметьте «Частные сети». Если окно закрыли или нажали «Отмена», клиент сервер не найдёт. Тогда добавьте правило вручную (PowerShell от имени администратора, путь замените на свой):

```
New-NetFirewallRule -DisplayName "2Nouta" -Direction Inbound -Program "C:\путь\к\2Nouta.exe" -Action Allow -Profile Private
```

Сеть Wi-Fi в Windows должна быть отмечена как «Частная»: для «Общедоступной» сети входящие подключения обычно закрыты.

IP вводить не нужно, клиент ищет сервер сам:

1. Сначала проверяет последний найденный адрес из `last_ip.txt`.
2. Если там никто не ответил, определяет свой IP и маску подсети и параллельно опрашивает все адреса подсети на порту `55556` (таймаут 300 мс на адрес). Каждому адресу отправляется `DISCOVER`, сервер отвечает `HERE <имя компьютера>`.
3. Если ответило несколько серверов, выбирается тот, что ответил быстрее всех.
4. Клиент подключается к найденному серверу на порт `55555` и сохраняет его IP.

Если сервер не найден, в окне клиента появится сообщение. IP можно ввести вручную в поле «IP сервера» или нажать «Найти в сети» ещё раз. IP можно передать и аргументом, тогда поиск не выполняется:

```
2Nouta.exe client 192.168.0.193
```

IP сервера можно узнать на Ноутбуке 1 командой `ipconfig` (строка «IPv4-адрес»). Проверка связи с Ноутбука 2:

```
ping 192.168.0.193
Test-NetConnection 192.168.0.193 -Port 55556
```

- ping не проходит — ноутбуки в разных сетях или включена изоляция клиентов;
- ping проходит, но `TcpTestSucceeded : False` — брандмауэр на Ноутбуке 1 блокирует `2Nouta.exe`;
- включён VPN — клиент может искать сервер не в той подсети; отключите VPN или введите IP вручную.

Если соединение пропало, нажмите в окне клиента «Переподключиться»: клиент снова загрузит каталог и покажет последнюю выбранную модель. Сервер после отключения клиента сам снова ждёт подключения.

## Запуск из исходников

Без сборки, если установлен Python с Tkinter и Pillow (`pip install pillow`): `python main.py` (или `python main.py server`, `python main.py client 192.168.0.193`). Сервер берёт данные из папки `data` рядом с `server.py`.

## Как работает

1. Сервер открывает окно сразу и ждёт клиентов на порту `55555` в отдельном потоке, у каждого клиента свой поток. В окне виден статус: «Ожидание клиента...», «Клиент подключён», «Соединение потеряно».
2. Клиент подключается к серверу и запрашивает список моделей. На каждую команду сервер отвечает одной строкой `OK <данные>` или `ERROR <текст>`:
   - `LIST` — список моделей (JSON с `id` и названием);
   - `SELECT <id>` — сервер показывает модель у себя;
   - `MODEL <id>` — характеристики и подписи к фото (JSON);
   - `PHOTO <id> <номер>` — одно фото в base64. Фото идут отдельными ответами, по одному, так что ответ остаётся в пределах `MAX_MESSAGE_SIZE`.
3. При выборе модели старая информация на обоих экранах сразу заменяется на «Загрузка…». Каждый выбор получает номер. Если, пока шла загрузка, выбрали другую модель, ответы по старому выбору отбрасываются. Если модель выбирают несколько клиентов, сервер показывает последний выбор.
4. Сервер ищет модель только среди `id` из `data/models.json` и не подставляет строку клиента в путь к файлу. На неизвестную команду, неверный `id` или номер фото он отвечает `ERROR`. Слишком длинная строка без `\n` закрывает соединение.
5. Каждое сообщение заканчивается символом `\n`. TCP передаёт поток байтов, поэтому несколько сообщений могут прийти одним куском или одно сообщение несколькими. Обе стороны складывают данные в буфер и разбирают их по `\n`.
6. Сеть и разбор фото на клиенте работают в фоновых потоках. Окно Tkinter обновляется только из главного потока: фоновый поток передаёт изменения через `root.after(0, ...)`. Если сервер недоступен или ответил ошибкой, клиент пишет это в окне.
7. Поиск работает на отдельном порту `55556`, чтобы проверочные подключения не мешали каналу команд на `55555`.
8. При закрытии окна сокеты закрываются.
